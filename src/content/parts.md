## The problem these parts solve

Loop-ended, repeat-heavy constructs are difficult to obtain: commercial
synthesis providers decline them, and the inverted repeats that make them work
are exactly what makes them hard to assemble. The response was to stop treating
the construct as one thing to be ordered and start treating it as a set of
modules to be combined.

That modularity is what makes the platform argument on
[the description page](/description) true, swap the targeting sequence, keep
everything else.

## Documentation on the Registry

Each part page carries the same five sections, so a visitor arriving from the
Registry rather than from this wiki still gets the full picture:

| Section              | What goes in it                                              |
| -------------------- | ------------------------------------------------------------ |
| **Design**           | How it was conceived, the rationale, any modelling behind it |
| **Experiment**       | Protocols, conditions, results, troubleshooting              |
| **Characterisation** | How it behaves, quantitatively where possible                |
| **Application**      | How it was used in a system                                  |
| **Discussion**       | Limitations, comparisons, future directions                  |

Write the design-build-test-learn story onto the part page itself, not only
here. A judge may never see this wiki page.

## Improved parts

Where a part builds on an existing one, state what the improvement is and what
the original was used as a control for. An improvement claimed without a
side-by-side comparison is not an improvement.
